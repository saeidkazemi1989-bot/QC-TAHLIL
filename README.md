# سامانه گزارشات کیفیت (QC-TAHLIL)

داشبورد تحلیلی گرافیکیِ کیفیتِ تولید که از چهار فایل اکسلِ شما یک **پایگاه داده** می‌سازد و تمام
نمودارها، شاخص‌ها و جداول را از همان پایگاه می‌خواند.

هر وقت فایل‌های جدید را در پوشه داده بریزید (یا از داخل برنامه بارگذاری کنید)،
فقط با زدن یک دکمه همه چیز به‌روز می‌شود — بدون تغییر کد و بدون ساخت دوباره پایگاه داده.

---

## ۰. مسیر داده (مهم)

```
گزارش‌های خام راهکاران (data/raw)        ← چهار فایل خروجیِ سیستم
        │
        │  npm run clean      (اجرای qc.py — ابزار تبدیل شما)
        ▼
گزارش(های) تمیز (data/clean/QC Report*.xlsx)
        │
        │  npm run import     (ETL)
        ▼
پایگاه داده SQLite (data/qc.db)
        │
        ▼
داشبورد (نمودارها، شاخص‌ها، جداول)
```

داده‌های پراکنده‌ی خروجیِ راهکاران ابتدا توسط ابزار تبدیل شما (`qc.py`) به «گزارش تمیز»
تبدیل می‌شوند؛ داشبورد فقط این گزارش‌های تمیز را می‌خواند. مزیت‌ها:

- تاریخ‌ها شمسی و یکدست، کد و شرح عیب نرمال‌سازی‌شده، عبارت‌های همتاساز حذف شده
- اطلاعات محصول (برنچ، خانواده، گروه نهایی) به هر ردیف الصاق شده
- ردیف‌های تکراریِ گزارش ماه قبل دیگر تکرار نمی‌شوند (`--history`)
- مخرجِ PPM هر گزارش دقیقاً از مراکز کاری همان گزارش گرفته می‌شود

> توجه: فایل‌های موجود در `data/raw` فقط ورودیِ ابزار تبدیل هستند و مستقیماً وارد
> داشبورد نمی‌شوند.

دستورهای اصلی:

| دستور | کاری که می‌کند |
| --- | --- |
| `npm run clean` | اجرای ابزار تبدیل روی فایل‌های `data/raw` و ساخت گزارش تمیز در `data/clean` (هرگز فایل تمیز موجود را بازنویسی نمی‌کند) |
| `npm run import` | بارگذاری گزارش‌های تمیزِ `data/clean` در پایگاه داده |
| `npm run refresh` | هر دو مرحله پشت سر هم (تمیز کردن + بارگذاری) |

## ۱. راه‌اندازی

### الف) بدون هیچ نصبی — فقط ببینید

فایل **`QC-Dashboard.html`** را دبل‌کلیک کنید. این یک فایل مستقل است
(حدود ۲ مگابایت) که داده‌ها و نمودارها درون خودش هستند؛
نه سرور می‌خواهد، نه اینترنت، نه نصب Node.js.

- محدودیت این نسخه: فقط انتخاب منبع عیب (حین تولید / بازرسی) فعال است،
  فیلترهای دیگر و بارگذاری داده جدید در آن وجود ندارد.
- بعد از هر به‌روزرسانی داده، با `npm run export` دوباره ساخته می‌شود.

> نکته: ابتدا فایل زیپ را **Extract** کنید؛ باز کردن فایل‌ها از داخل پوشه زیپ
> (مسیرهایی شبیه `...\Temp\....zip.73d\...`) در هیچ برنامه‌ای کار نمی‌کند.

### ب) نسخه کامل (ویندوز)

1. پوشه زیپ را Extract کنید و وارد پوشه پروژه شوید.
2. اگر Node.js نصب ندارید، یک‌بار آن را از [nodejs.org](https://nodejs.org) نصب کنید
   (**نسخه ۲۲ LTS یا بالاتر توصیه می‌شود**).
3. روی **`start.bat`** دبل‌کلیک کنید. مرورگر به‌طور خودکار روی `http://localhost:3000` باز می‌شود.

> **نکته مهم:** فایل `public/index.html` را با دبل‌کلیک باز نکنید. برنامه یک سرور دارد که
> داده‌ها را از پایگاه داده می‌خواند و در حالت `file://` اجرا نمی‌شود
> (فقط پیام «در حال بارگذاری سامانه» نمایش داده می‌شود).
> فایل `بخوانید-قبل-از-اجرا.txt` هم همین توضیح را دارد.

### هر سیستمی (دستی)

```bash
npm install          # نصب وابستگی‌ها (یک‌بار)
npm start            # اجرای سامانه روی پورت 3000
```

سپس در مرورگر آدرس `http://localhost:3000` را باز کنید.
روی لینوکس/مک می‌توانید به‌جای آن `./start.sh` را اجرا کنید.

در اولین اجرا، اگر پایگاه داده خالی باشد، فایل‌های اکسلِ موجود در `data/raw` به‌طور خودکار
بارگذاری می‌شوند.

دستورهای دیگر:

| دستور | کاربرد |
|---|---|
| `npm start` | اجرای سرور و رابط کاربری |
| `npm run import` | بارگذاری/به‌روزرسانی داده‌ها از فایل‌های اکسل (بدون اجرای سرور) |
| `npm run reset` | حذف پایگاه داده و بارگذاری دوباره از صفر |
| `npm test` | خودآزمایی: اجرای همه پرس‌وجوهای تحلیلی با ترکیب‌های مختلف فیلتر |
| `npm run export` | ساخت/به‌روزرسانی فایل تک‌صفحه‌ای `QC-Dashboard.html` |

> **نیازی به نصب SQL Server یا دیتابیس جداگانه نیست.** برنامه از SQLite استفاده می‌کند:
> در Node ۲۲ به بالا از موتور داخلی خود Node استفاده می‌شود (بدون هیچ کامپایل اضافه)؛
> در نسخه‌های قدیمی‌تر در صورت نیاز از بسته `better-sqlite3` استفاده می‌شود.

برای اجرا روی شبکه داخلی با پورت دیگر:

```bash
PORT=8080 npm start
```

## ۲. ورود و سطح دسترسی

ورود در حال حاضر «انتخاب نقش» است (بدون رمز عبور، برای شروع سریع روی شبکه داخلی)؛
در صورت نیاز می‌توان برای هر کاربر رمز گذاشت (مدیر سیستم > کاربران).

| نقش | صفحه‌های قابل مشاهده | تمرکز |
|---|---|---|
| **مدیر ارشد** | نمای کلی، داشبورد مدیریتی، گزارش تولید، راهنما | روندها، مقایسه دوره‌ها، تصمیم‌گیری |
| **کارشناس کیفیت** | نمای کلی، تحلیل حین تولید، اسناد بازرسی، PFMEA، گزارش تولید، رکوردهای تفصیلی، راهنما | ریشه‌یابی: پارتو، 6M، قطعه/تامین‌کننده، زمان‌های تعمیر، جدول رکوردها |
| **مدیر سیستم** | همه صفحه‌ها + مدیریت داده و کاربران | بارگذاری فایل، به‌روزرسانی داده، تعریف کاربر و تنظیمات |

کنترل دسترسی فقط در ظاهر نیست؛ سرور هم برای هر نقش محدودیت اعمال می‌کند
(مثلاً مدیر ارشد به رکوردهای تفصیلی و بخش مدیریت دسترسی ندارد).

## ۳. صفحه‌ها

1. **نمای کلی** — شش شاخص کلیدی + روند تولید/عیوب/PPM + پارتو عیوب + توزیع بر ایستگاه + محصولات پرعیب + تحلیل 6M یا شیفت.
2. **داشبورد مدیریتی** — روند ماهانه با مقایسه دوره قبل، مقایسه برنچ‌ها، دسته‌های عیب،
   نمودار تغییرات PPM ایستگاه‌ها نسبت به دوره قبل، نمودار پراکندگی «تولید در برابر PPM»،
   جدول محوری (گروه محصول × دسته عیب) و جدول عملکرد محصولات.
3. **تحلیل عیوب حین تولید** — پارتو کدهای عیب، ایستگاه، حوزه فرآیندی، عامل مسبب (6M)،
   اقدام تعمیرات، خانواده قطعات، قطعات پرمشکل، ثبت‌کننده، حالت خرابی، اپراتور، فرآیند OPC،
   جدول زمان‌های تعمیراتی و جدول محوری (کد عیب × ایستگاه).
4. **تحلیل اسناد بازرسی (OQC)** — پارتو دلایل مردودی، ایستگاه بازرسی، عنوان عملیات آزمایش،
   شیفت، محصولات با بیشترین مردودی، جدول محوری (محصول × دلیل).
5. **تحلیل PFMEA / RPN** — جدول و نمودار بحرانی‌ترین حالت‌های خرابی بر اساس
   RPN = شدت × وقوع × تشخیص و نمودار شدت-وقوع.
6. **گزارش تولید** — تولید روزانه/هفتگی/ماهانه، مراکز کاری، حوزه فرآیندی، برنچ، پرمحصول‌ترین کالاها.
7. **رکوردهای تفصیلی** — مشاهده، جست‌وجو، مرتب‌سازی، صفحه‌بندی و خروجی Excel (CSV) از ریز داده‌ها.
8. **مدیریت داده و کاربران** — بارگذاری فایل اکسل، به‌روزرسانی داده‌ها، مشاهده وضعیت فایل‌ها،
   تعریف کاربر/نقش و تنظیمات (مثل هدف PPM).
9. **راهنما و واژه‌نامه** — توضیح هر شاخص، منبع داده‌ها و روش به‌روزرسانی.

در کنار هر شاخص یک دکمه **؟** هست که همان لحظه توضیح آن شاخص (فرمول و معنی) را نشان می‌دهد؛
بنابراین هر کسی با یک نگاه متوجه می‌شود عدد چه می‌گوید.

## ۴. شاخص‌ها و نحوه محاسبه

| شاخص | فرمول | توضیح |
|---|---|---|
| تولید (مقدار سالم) | مجموع «مقدار سالم» سفارش‌های بازه | مخرج محاسبه PPM |
| تعداد عیوب (حین تولید) | مجموع «تعداد عیب» | هر مورد عیب ثبت‌شده روی محصول |
| تعداد واحد معیوب (بازرسی) | مجموع «تعداد ایراد» (بدون ردیف تکراری) | تعداد دستگاه‌های مردود |
| **PPM** | عیوب ÷ تولید × ۱,۰۰۰,۰۰۰ | عیب به ازای هر یک میلیون محصول؛ کمتر بهتر |
| نرخ ضایعات | ضایعات ÷ (سالم + ضایعات) × ۱۰۰ | درصد خروج از چرخه تولید |
| زمان رفع عیب | عیب‌یابی + رفع عیب + تست مجدد (ساعت) | زمان صرف‌شده برای برگرداندن محصول |
| RPN | شدت × وقوع × تشخیص | اولویت اقدام اصلاحی در PFMEA |

**نکته درباره اسناد بازرسی:** در این گزارش برخی عیب‌ها زیر دو «عنوان عملیات آزمایش» ثبت شده‌اند.
جمع ساده باعث بزرگ‌نمایی حدود ۲۳٪ می‌شود؛ سامانه برای هر (سفارش، کد عیب) فقط یک عملیات را
می‌شمارد (۵,۰۸۰ به‌جای ۶,۲۶۲ عدد خام).

**نکته درباره مخرج تولید:** تولیدِ مبنای PPM فقط سفارش‌هایی است که در منبع انتخابی
(حین تولید یا بازرسی) حضور دارند، تا صورت و مخرج کسر هم‌خوان باشند.

## ۵. منبع داده‌ها

| فایل | نقش | تعداد ردیف (نمونه فعلی) |
|---|---|---|
| `اطلاعات جامع کیفیت حین تولید (9).xlsx` | ریز عیوب ایستگاه‌ها (6M، قطعه، تعمیرات، PFMEA) | ۱,۷۶۳ |
| `گزارش عیب های سند بازرسی (8).xlsx` | نتایج بازرسی رسمی هر سفارش | ۲,۸۴۳ |
| `گزارش تعداد تولید به تفکیک سند عملکرد (2).xlsx` | تولید روزانه به تفکیک مرکز کاری | ۲,۰۸۲ |
| `گروه بندی محصولات.xlsx` | نگاشت کد محصول به برنچ/خانواده/گروه نهایی | ۲۸۱ |

تشخیص نوع فایل بر اساس **نام ستون‌ها** انجام می‌شود؛ بنابراین نام فایل مهم نیست و
می‌توانید فایل دوره‌های بعد را با هر نامی در پوشه بگذارید.

### روش به‌روزرسانی داده

**روش ۱ (از داخل برنامه):** مدیر سیستم > مدیریت داده و کاربران > انتخاب/کشیدن فایل اکسل >
بارگذاری و به‌روزرسانی خودکار.

**روش ۲ (بدون باز کردن برنامه):** فایل جدید را در پوشه `data/raw` بگذارید و:

```bash
npm run import
```

یا در صورت اجرا بودن سامانه، دکمه «به‌روزرسانی همه داده‌ها» را بزنید.

قواعد بارگذاری:

- هر فایل با نام خودش ثبت می‌شود؛ ردیف‌های همان فایل در هر بارگذاری **جایگزین** می‌شوند (تکراری ایجاد نمی‌شود).
- اگر چند فایل هم‌نوع (مثلاً دو دوره از گزارش حین تولید) در پوشه باشد، داده‌های هر دو با هم دیده می‌شود؛
  برای جایگزینی کامل، فایل قدیمی را حذف کنید یا همان نام را دوباره بارگذاری کنید.
- فایلی که از پوشه حذف شود، داده‌های آن در بارگذاری بعدی پاک می‌شود (با `removeMissing`).
- ابعاد (محصول، ایستگاه، کد عیب) پس از هر بارگذاری به‌طور خودکار بازسازی و طبقه‌بندی می‌شوند.

## ۶. ساختار پروژه

```
QC-TAHLIL/
├─ server/
│  ├─ index.mjs        # سرور Express، API تحلیلی، مدیریت داده، احراز هویت
│  ├─ etl.mjs          # خواندن اکسل و بارگذاری در پایگاه داده (idempotent)
│  ├─ analytics.mjs    # پرس‌وجوهای تحلیلی (شاخص، روند، تفکیک، ماتریس، PFMEA، زمان‌ها)
│  ├─ filters.mjs      # تبدیل فیلترهای رابط کاربری به شرط‌های امن SQL
│  ├─ db.mjs           # اتصال پایگاه داده، طرح جداول، تقویم شمسی، تنظیمات
│  ├─ schema.sql       # جداول بعد/واقعیت و نماهای تحلیلی
│  └─ jalali.mjs       # تقویم شمسی (تبدیل، هفته، فصل، نیم‌سال)
├─ public/
│  ├─ index.html       # صفحه اصلی (راست‌به‌چپ)
│  ├─ css/app.css      # شیوه‌نامه
│  ├─ js/              # app.js (چارچوب/فیلترها)، pages.js، charts.js، ui.js، glossary.js، jalali.js
│  └─ vendor/          # کتابخانه نمودار ECharts
├─ data/raw/           # فایل‌های اکسل (منبع داده)
└─ data/qc.db          # پایگاه داده SQLite (ساخته‌شده در اجرا، در گیت ذخیره نمی‌شود)
```

پایگاه داده SQLite است (یک فایل) و نیازی به نصب هیچ سرویس دیتابیسی ندارد.

## ۷. محدودیت‌ها و گام‌های بعدی

- بخش هزینه/ریالی عمداً حذف شده است (طبق درخواست): تمرکز روی شاخص‌های کمی است.
- ورود در حال حاضر بدون رمز است؛ برای استقرار روی شبکه، در صفحه مدیریت برای هر کاربر رمز بگذارید.
- در صورت نیاز می‌توان خروجی چاپی/صفحه‌بندی مدیریتی، هشدار خودکار روی آستانه PPM،
  و اتصال مستقیم به پایگاه داده ERP/سیستم کیفیت را هم اضافه کرد.
